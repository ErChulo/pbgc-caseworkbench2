# Reconciliation input binding

Reconciliation previously hashed result counts, mismatches, workbook and oracle identifiers, but not the values actually compared. Two successful comparisons with different expected or actual values could therefore receive the same result hash. Results now contain deterministic digests of the entire supplied oracle object and actual-values object; these digests are included in the result hash and exported evidence. Complete results require both inputs to be hashable. Malformed or non-finite inputs can have a null input digest only on blocked results. The comparison snapshots inputs before asynchronous validation so caller mutation cannot change the result midway.

Reconciliation evidence generation and review notes verify the result hash and required digest fields; an existing note cannot be overwritten without a review-history workflow. The evidence includes the complete tolerance profile. Non-finite oracle precision is rejected. The unused integer-rounding helper now implements half-to-even for exact binary half-integers instead of JavaScript's `Math.round` behavior; no rounding operation was added to reconciliation or workbook generation.

These digests establish consistency, not provenance or authority. A caller can still assert an oracle's identity, trust and execution-evidence text; independent authentication, durable byte-bound execution artifacts, approved numerical/decimal policy, and reviewer authorization remain required. JavaScript binary floating-point comparison remains unsuitable where exact decimal behavior is required. Old reconciliation results lack the new input digests and must be regenerated, not treated as equivalent. Synthetic tests cover changed inputs that both pass, caller mutation, malformed values, forged evidence and half-even boundaries. No Excel or external oracle execution was performed.

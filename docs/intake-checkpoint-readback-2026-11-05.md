# Intake checkpoint readback

Evidence intake now reads back a newly written snapshot and manifest, the bounded intake event history after append, and the current manifest pointer. Before completion it rechecks the pointer and the selected checkpoint, including the standalone snapshot, after the review snapshot write. A cached checkpoint's complete manifest bytes are pinned by SHA-256 for the current session, in addition to comparing the parsed checkpoint projection and snapshot identity. A structurally valid change to manifest metadata therefore cannot silently reuse a cached checkpoint.

If readback fails, intake uses the existing partial-write failure path and does not report successful completion. An existing snapshot at the expected path is compared with the selected snapshot; a mismatching orphan is blocked, not overwritten. Intake events and checkpoint records are limited to 16 MiB, and pointers to 64 KiB. An over-limit history blocks further intake rather than truncating it.

These checks establish observed consistency, not authenticity or atomic transactions. On initial restoration or first discovery of an existing manifest, the session pin is derived from the structurally accepted local bytes, not an independent authority. Another window or external process can change files between checks or after completion; partial files, an appended event, or a pointer can remain after a failure. Governed recovery, cross-window coordination, identity, and native office filesystem validation remain necessary. Previously invalid records are not repaired by this change.

Synthetic fault-injection tests exercise changed snapshot, manifest, event, pointer, cached metadata, and oversized history, including a built offline file. The full Chromium synthetic suite passed 116 tests with 3 skipped; the full unit/integration suite passed 1,213 tests across 158 files using the authorized hash-verified local Data Dictionary. This is not approval for real-data use.

A subsequent hardening pass also rechecks the intake event history after the review write. Synthetic fault injection changes each of the event history, snapshot, manifest and pointer during that later write and confirms intake remains blocked. This narrows an observed-change window; it still cannot prevent changes after the last read or establish cross-window atomicity. The complete Chromium suite subsequently passed 120 tests with 3 skipped against the isolated build; unit/integration results remained 1,213 passed.

Case restoration now also reads the standalone snapshot with the 16 MiB record limit and compares its canonical JSON to the snapshot embedded in the accepted manifest. A missing, unreadable, oversized or mismatching standalone snapshot blocks evidence restoration without changing files. Older or partially written cases without a matching standalone snapshot now require governed inspection and recovery; the application does not recreate it. This comparison does not authenticate either copy, replay intake history, or provide cross-window atomicity. Synthetic restoration tests cover missing, mismatched and oversized snapshots; the full Chromium suite passed 123 tests with 3 skipped on the isolated build, and 1,213 unit/integration tests passed with the authorized local dictionary.

# Bounded workbook preflight — 2026-11-07

The passive workbook parser now uses the bounded OOXML stream preflight before passing ZIP-based workbooks to SheetJS. It inventories the central directory, rejects unsafe/colliding paths and unsupported methods, streams every entry in small compressed chunks, and checks observed expansion and local/central consistency. Only relationship data is retained by the preflight. Workbook limits are 32 MiB input, 2,000 parts, 64 MiB total expanded, 32 MiB per part, 8 MiB per XML part and 4 MiB per relationship part. Legacy binary workbooks are also subject to the input-size limit but remain marked `legacy-container-unverified` and are not covered by ZIP preflight. The workbook parser version is 1.4.0 for success and failure.

These limits are deliberately conservative and can reject legitimate workbooks. Previously accepted sources may fail reinspection; profile decisions must not be assumed current when verification fails. Intake currently loads file bytes before this parser runs, so these limits do not bound all intake memory. The preflight does not establish CRC integrity, complete ZIP structure or central offset equivalence, complete XML safety, malware absence, or SheetJS behavior for every malformed input. SheetJS separately parses the original bytes after preflight, so this is not a complete ZIP-bomb or workbook security defense. General archive handling and the approved Data Dictionary parser have different controls. Source authority, user identity, participant routing, actuarial approval and final output remain separate gates.

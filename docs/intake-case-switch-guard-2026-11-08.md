# Intake case-switch guard — 2026-11-08

File intake now acquires a same-session guard immediately when a user selects files, including the existing short delay before processing begins. The active-case banner disables return to the workspace home and explains that the user must finish or stop intake first. Workspace selection and case activation also refuse to run while the guard is held; the orchestrator checks that intake is active and still belongs to the selected case before processing begins. The guard is released when processing finishes or fails. An intake exception now warns that files or records may have been saved and should be inspected before retrying, rather than claiming that all prior files are unchanged.

A synthetic Chromium test delayed a preserved-object write and checked that the case could not be left until intake completed. The test passed both on the development origin and from an isolated built `file://` artifact with HTTP blocked; it used an in-memory workspace. Existing synthetic intake interruption, resumption, and correction-race tests also passed. Typecheck, lint, format, schema and contract checks and the isolated single-file build/verifier passed. The full suite reported 1,195 passing tests, four skipped and one failing Data Dictionary suite because approved Git LFS bytes are absent.

This is a same-session navigation guard, not a cross-window lock or transaction. It does not serialize all review operations with intake, prevent external file changes, cancel a write already underway, or prove recovery after process/browser termination. Other case-changing paths and concurrent operations still need formal office-environment verification. No native filesystem, real case data, Excel execution or human approval was tested; the existing browser-externalized Node warning remains. The real-data readiness gates remain open.

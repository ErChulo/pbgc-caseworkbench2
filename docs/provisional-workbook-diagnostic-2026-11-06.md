# Provisional workbook diagnostics — 2026-11-06

The generated-XLSX gate can provide a local JSON diagnostic after model validation. It records the case ID, recorded model hash, computed validation evidence and its content hash, outcome and blocking reason, read-back status and method, limitations, and a typed diagnostic content hash. For a successful check only, it also binds the exact generated XLSX byte hash and size. The UI displays the separate hash of the exact downloaded JSON bytes. The report is capped at 8 MiB; its construction verifies validation evidence and recomputes the model hash. If a successful diagnostic cannot be constructed, no workbook is published. Where diagnostic construction is safe, blocked model, preflight, serialization, read-back and digest outcomes can be downloaded without a workbook. Failures before a model can be safely validated do not produce a report.

The in-memory Blob is bound to the current case and cleared with workbook invalidation, a new build, case reset, or an error. The UI labels it provisional and warns that it may contain case details. Store and share it only under applicable local case-data controls. It is not signed or authenticated, and neither hash establishes source authority or reviewer identity. The same library writes and reads the generated XLSX; this does not establish formula execution, correctness, reconciliation, actuarial approval, or release readiness. It is not a final casework output artifact.

## Verification and scope

Synthetic tests cover successful diagnostic and XLSX bindings, hashes, blocked model findings and serialization failure; a component test covers downloading availability with a blocked workbook. The production-path Chromium test confirms no diagnostic is shown when the build stops before model generation. Successful and model-invalid diagnostic downloads have not been demonstrated end-to-end in a production browser path: unresolved I/B routing blocks that path earlier.

Before the final read-back error classification adjustment, typecheck, lint, formatting, schema and contract checks passed; 140 targeted tests and all 55 Chromium tests passed. The full test suite reported 1,127 passed and four skipped, with one failed suite because the approved Data Dictionary is an LFS pointer rather than the required workbook. The quality command stopped at that failure. After the adjustment, typecheck, targeted lint and 15 builder/read-back tests passed; an isolated build and single-file verification passed, as did three targeted Chromium production-blocker and offline tests. The build retains the existing browser-externalization warning for `node:fs/promises`. This is not evidence of Excel, BCV, ValTool, Runtime, or human execution or approval. The pre-existing modified `dist` file was not replaced by the isolated build.

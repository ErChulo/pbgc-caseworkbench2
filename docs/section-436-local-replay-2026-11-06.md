# Local Section 436 evaluation replay — 2026-11-06

The case output panel can now check a locally selected Section 436 evaluation JSON file for the active case. The check is in memory only; it does not save or link the file. It enforces a 1 MiB input limit, at most 500 facts and 500 rules, at most 4,000 fact/rule citations, valid UTF-8, the approved evaluation schema and timestamp, exact active-case ID, and the typed deterministic payload hash. It recomputes the evaluation using the current local evaluator and rejects a payload that does not replay to the same hash, even if a changed conclusion was rehashed. The panel displays the evaluated status, the supplied payload's content hash, and a separately calculated hash of the exact selected bytes. File replacement and active-case changes discard stale in-flight results.

This is **consistency checking, not independent validation**: the replay uses the same implementation and input assertions. It does not authenticate the file, author, source documents, citations, reviewer, approval, or operational metadata; the content hash excludes operational metadata. The displayed file hash is calculated, not compared with a trusted external hash. A matching replay can still be blocked or inconclusive, and a completed replay does not establish actuarial correctness, authority, execution, or release readiness. The package remains blocked. The current schema fixes the evaluator version string, so replay compatibility with the current implementation is tested directly rather than inferred from that string. Case files can contain sensitive details; the UI warns users to apply local case-data controls. No case data is transmitted.

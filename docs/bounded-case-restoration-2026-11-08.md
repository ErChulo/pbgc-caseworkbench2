# Bounded case restoration — 2026-11-08

Evidence checkpoint and review restoration now copy local JSON through strict, size-checked chunk reads. Inventory and review pointers have a 64 KiB limit; checkpoint and review snapshots have a 16 MiB limit. Over-limit, incomplete, unreadable, malformed or unverifiable records block case actions with an explanation rather than being parsed or replaced. Existing snapshots inspected during review persistence and checkpoint reuse are subject to the same record limit. The UI states the limits when restoration is blocked.

New review snapshots and inventory checkpoints are checked against the 16 MiB limit before they are written. Intake also preflights the current review snapshot before publishing its new checkpoint pointer. An exception during intake now blocks further case actions and warns that some files or records may have been saved; the user must inspect the workspace before reopening. This is not rollback: a concurrent review can change after preflight, other writes may already have occurred, and reopening does not itself prove a missing or partial history is complete. Normal partial/interrupted intake outcomes retain their existing behavior.

Synthetic Chromium tests rejected oversized inventory and review pointers and records, exercised an intake write exception, and passed existing restore, intake, and governed production paths. An oversized pointer was also rejected from an isolated built `file://` artifact with HTTP blocked. The tests use an in-memory workspace; native filesystem behavior was not tested. Typecheck, lint, formatting, schemas, contracts, isolated build and single-file verifier passed. The full suite reported 1,200 passed, four skipped and one Data Dictionary failure because the approved Git LFS workbook is unavailable.

These are operational bounds, not approved business limits or authenticity checks. Legitimate cases exceeding them require an approved alternative workflow or a governed change, not silent truncation. The bounds do not cover every local JSON read, constrain every collection or guarantee bounded CPU time. Hashes and readback do not establish author identity, source authority, cross-window locking or atomic transactions. External execution and actuarial approval remain unverified; the application remains not ready for real-data office testing. Vite continues to report the existing browser-externalized Node module warning.

# Intake inspection byte binding — 2026-11-07

Previously intake preserved and verified source bytes, then independently read the selected `File` again for binary screening and passive extraction without checking that this later read matched the preserved hash. Intake now reopens the preserved content-addressed object, reads it in fixed-size chunks, checks its size, chunk boundaries, and SHA-256, and uses those privately copied bytes for screening and extraction. A mismatch or read failure leaves the item failed, excludes it from the new snapshot, and makes the inventory partial; an already written object may remain as an orphan. This is consistency verification, not authentication or an atomic transaction with other windows.

Intake now fails files above 32 MiB before hashing or preservation because its screening and parsing still require an in-memory input. The item is reported as failed and excluded from the snapshot; smaller or streaming workflows are not implied. This conservative limit can exclude legitimate office evidence and needs an approved larger-file workflow before real-data readiness. It does not limit the total size of a selection, prevent all memory pressure from expanded content, secure all other file-upload paths, or replace malware and ZIP-bomb defenses.

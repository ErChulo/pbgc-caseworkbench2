# Browser and Node rule-loading boundary

The architecture rule loader previously imported `node:fs/promises` in a module also used by the browser, causing Vite to substitute a browser-external stub and emit a warning. The production app uses the bundled, parsed rule text and does not need Node filesystem access. Node-only file loading and the glossary file convenience function now live in `web/src/adapters/node/architecture-rule-files.ts`; the browser-facing domain modules do not import them. The quickstart now points Node tooling to that adapter. No rule contents, approval checks, policy hashes or actuarial calculations were changed.

A Vite pre-resolution guard rejects direct imports of Node builtins in the browser graph rather than allowing a silent stub. Integration tests exercise static and dynamic `node:` imports and a bare builtin, plus Node glossary loading and a missing-file failure. This guard is not a network, dependency, supply-chain or complete JavaScript security audit; runtime behavior and third-party code still require independent review. The single-file verifier also checks only its documented patterns.

The isolated production build completed without the former externalization warning and passed the single-file verifier. With the approved Data Dictionary supplied locally, all 1,210 unit, integration and contract tests passed across 157 files. Typecheck, lint, formatting, schema and contract checks passed. Six Chromium tests passed, covering the synthetic governed production workflow on development and built `file://` origins, the local dictionary, and offline DOCX extraction with a simulated workspace. The built-file tests block HTTP and do not demonstrate native office filesystem behavior, independent calculation validation or approval.

The separate DOCX MIME safety hold remains unresolved: its screening policy and persisted review history need an explicit versioning and re-screening approach before changing it. Real-data office readiness remains blocked by the gates in `in-office-real-data-readiness-2026-11-06.md`.

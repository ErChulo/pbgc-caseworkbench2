# Workbook builder input snapshot — 2026-11-07

Both workbook builder entry points now capture caller-supplied input before any asynchronous validation, hashing, or construction. The compiled entry point also captures the supplied compilation result. Nested population maps and their values are copied by `structuredClone`; uncloneable inputs fail closed with `INPUT_SNAPSHOT_FAILED`. The fresh compiler check, target collision check, and participant-routing blocker operate on the captured build specification, and the workbook is built from that same captured input.

Synthetic unit tests exercise mutations during generation, including removal of an input mapping while compilation is pending, and mutation of nested population maps in the preliminary builder. This is a consistency safeguard, not approval of population routing, source authority, actuarial calculations, or final output. It does not make returned workbook objects immutable; downstream consumers must continue to validate their own captured inputs. Snapshotting also creates an in-memory copy, so large inputs consume additional memory.

# Bounded DOCX/PPTX passive inspection — 2026-11-07

Passive DOCX and PPTX extraction previously expanded the full ZIP with no local limits. It now first inventories central-directory entries without expanding them, rejects unsafe/colliding names, unsupported compression and excessive declared sizes/counts, then streams each entry in small compressed chunks and checks observed expanded sizes against the inventory before publishing any result. Limits are 32 MiB compressed input, 2,000 entries, 64 MiB total expanded, 32 MiB per part, and 8 MiB per XML or relationship part. Only XML and relationship bytes are retained for extraction; expansion failures reject the whole package. Relationship extensions are checked case-insensitively. The passive parser version is now 1.1.0, including failed results; reinspection may differ from older extraction records.

These are conservative resource and consistency checks, not a complete ZIP, CRC, encryption, XML, relationship, macro, malware, or ZIP-bomb security validator. At this milestone the XLSX/legacy workbook and general archive paths had different protections and were not covered by this change; see `docs/bounded-workbook-preflight-2026-11-07.md` for the subsequent ZIP-based workbook preflight. Limits may reject legitimate large documents and require governed operational review before production use. Extraction and source safety do not establish evidence authority, completeness or human approval.

Synthetic integration tests cover normal multi-chunk extraction, external relationships, uppercase relationship extensions, oversized XML, too many parts, unsafe/colliding paths, forged declared sizes, central/local mismatch and truncation. Typecheck, lint, formatting, schema and contract checks passed; the full suite reported 1,187 passed, four skipped and one failed Data Dictionary suite due to missing approved LFS bytes. An isolated single-file build and verifier passed. Chromium ran the governed synthetic pipeline on development and built-file origins and a synthetic DOCX extraction from the built file, with HTTP blocked in file tests and an in-memory workspace. Native filesystem and real office environments were not tested.

The DOCX browser test uses generic `application/octet-stream`: a separate existing screening rule treats ZIP signatures with declared DOCX MIME as a media mismatch and places them on a safety hold. That behavior was not bypassed or changed, and a governed remedy remains open. The browser-externalized Node module warning and other in-office readiness gates remain open.

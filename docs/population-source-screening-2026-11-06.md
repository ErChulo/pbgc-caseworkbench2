# Population source screening and replay

The byte-bound population verifier now reconstructs the workbook profile and re-detects its candidate from the supplied source bytes before replaying the decision. A self-consistent candidate that does not match the current detector output is rejected. This is a consistency check, not proof of source eligibility, reviewer identity or approval authority. The verifier is not yet wired into the wizard; approved participant selection and field mappings remain required before I/B routing can be enabled.

Workbook passive inspection now examines OOXML relationship parts and package names, flags external or ambiguous relationships, data connections and active parts, and marks legacy binary workbooks unverified. It applies preliminary ZIP entry, declared expansion and relationship-size limits and rejects ambiguous paths or missing required parts. The detector version changed, so older decisions must be re-evaluated. These conservative checks can block legitimate workbooks, including legacy XLS or unusual OOXML packages. They do not authenticate a workbook or establish that it is harmless: ZIP size metadata can be dishonest, relationship inspection is not a complete XML/package validator, and the workbook library still processes the supplied bytes. This is not a hardened sandbox or a complete ZIP-bomb defense. The relationship screen is shared with DOCX and PPTX.

Synthetic tests cover forged candidates, external/ambiguous relationships, entity declarations, duplicate paths, oversized relationship metadata, connection parts and legacy XLS. No participant PII or actual source documents are included. The full test suite still depends on the approved Data Dictionary LFS object, which was inaccessible in this environment. Browser offline execution and Excel calculation were not demonstrated.

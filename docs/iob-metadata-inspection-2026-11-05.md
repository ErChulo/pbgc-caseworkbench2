# Explicit I/O/B metadata inspection

The three `reference/approved-v1-workbooks` LFS pointers were matched by SHA-256 and size to files in the source collection and inspected locally, without running formulas or macros. The files are not included in this change. Their current applicability and authorization for a specific case have not been established. Structural inspection found I/O/B-like marker rows at different positions across example sheets, sometimes with multiple candidate rows. Row one contains populated cells on the calculation sheets. These observations do not establish a universal metadata row, target layout, participant mapping, or B-cell semantics. Legacy `mySort` sheets were observed but must not be recreated.

The population row inspector now permits an optional explicitly selected metadata row, distinct from the selected source row and header row. It checks the approved population profile by replaying and re-reading its case-bound source using the existing verification path, then reports the exact uppercase I, O, or B markers at selected binding columns. Missing, blank, formula, error and other cells remain distinct; formulas are not evaluated. It verifies exact row-one headers and rejects duplicate bindings or invalid columns. No automatic row discovery, inference, routing, approval, persistence or workbook write occurs. Metadata observations are separate from the existing record content hash. Changes to the selection clear the view.

This is an advisory inspection aid, not resolution of population routing or the formula target collision. These and the formula evidence, authorized policy, external validation and final-release gates remain open. The app is not ready for in-office real-data testing.

Follow-up verification: synthetic Chromium workflows exercised the metadata view against a source-bound workbook in both development and isolated single-file `file://` builds. They check I/O/B display, clearing, rejecting a metadata row equal to the selected data row, and failing when source bytes change. Additional unit tests check missing, blank, error, formula, unsupported and duplicate cell observations without displaying stored error values. These are synthetic tests, not office or external calculation validation.

# Population routing preflight

When a current BuildSpec and an explicitly inspected local population row are both available, the row view now reports potential routing issues without moving values or changing workbook generation. It compares case and population decision/profile lineage, source sheet and explicit field names, observed value states, input and B targets, row-one targets, duplicate mapping targets, input/formula overlaps, and formulas sharing a physical target across scenarios. It shows at most 50 issues and never displays participant values in the issue report. These checks do not validate or approve the BuildSpec, prove source eligibility or reviewer authority, choose a participant, define B-cell semantics, approve mappings, or authorize routing. A clean report does not lift the existing generation blocker. An unavailable BuildSpec is stated explicitly; a blocked BuildSpec cannot yet use this report.

Synthetic unit and component tests cover valid-looking input, lineage mismatch, header targets, duplicate targets, formula overlap and collisions, B semantics, source mismatch, missing and blank data, and invalidated BuildSpec display. The full unit/integration suite passed 1,233 tests in 160 files; all 134 synthetic Chromium tests passed with the approved local Data Dictionary. The isolated single-file build and verifier and static, schema and contract checks passed. The Chromium workflow covers row inspection but does not yet reach a complete BuildSpec and therefore does not exercise the preflight display in a browser; component tests do. No participant data was used. Native office behavior, external workbook execution, independent validation and human approval remain unverified.

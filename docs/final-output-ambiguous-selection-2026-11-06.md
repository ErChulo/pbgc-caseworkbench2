# Final-output ambiguous selection — 2026-11-06

The final-output input helper previously selected the first approved population projection and the last linked artifact of each type. Restored, duplicated or conflicting local records could therefore make array order decide which hash appeared in the package. The helper now includes a population hash only when exactly one candidate is marked approved, its effective hash is valid, and it matches that candidate's current workbook-profile hash. Multiple approved candidates, a missing hash, or a mismatch leave the population stage blocked. It includes a linked artifact type only when exactly one reference of that type exists; duplicates, including identical references, are not silently deduplicated or selected. Other unique types remain available. Re-linking an artifact through the existing UI replaces references of that type. Blocker wording now says that an unambiguous artifact or single matching population profile is required.

These checks prevent arbitrary selection but do not establish that a population profile or linked artifact is authentic, source-verified, actuarially correct, authorized or approved. All final package stages remain blocked pending the stronger evidence and approval gates already documented. This change does not implement participant routing, multi-population case selection, artifact authority, or conflict adjudication. An authorized reviewer must resolve multiple candidates; the package cannot infer which to use. Hash matches and local review labels remain consistency assertions, not authentication.

# Population row field-name reference

The local population row-inspection view now consults the session's approved Data Dictionary catalog for each explicitly entered field name. It reports an exact case-sensitive unique match with its table, an ambiguous name with a match count, or no match. The user can use the existing dictionary lookup for table-qualified details. If no dictionary is loaded, the view says so; selecting a new dictionary immediately clears the prior reference, including when the new file fails verification. Existing stale-selection protection prevents an earlier delayed load from replacing a later selection.

This is advisory reference information only. A name match does not establish that the field is appropriate for a participant, that the source header or value maps to it, that a user-defined field is invalid, or that a mapping, participant, routing, calculation, or output is approved. The row-inspection checks and I/B routing blocker are unchanged. The catalog stays in memory for the browser session, is not added to a case, and is not sent to a network service; no participant values are sent to the lookup. The same pinned size and SHA-256 verification applies before parsing the locally selected workbook; no macros execute.

Synthetic component tests cover unique, ambiguous and absent names, case sensitivity, clearing the reference and continued non-authorizing inspection. Chromium tests exercise the actual approved local dictionary, loading and rejecting altered bytes from both development and the isolated offline `file://` workflow, with outbound HTTP blocked. The full suite passed 1,227 unit/integration tests across 159 files and 134 Chromium tests, including the dictionary-dependent tests. Typecheck, lint, formatting, schema and contract checks, the isolated build and single-file verifier passed. The authorized workbook was not committed. This does not establish native office filesystem behavior, actuarial correctness, human authority, or real-data readiness.

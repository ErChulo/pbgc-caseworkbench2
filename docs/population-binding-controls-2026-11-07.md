# Explicit population binding controls — 2026-11-07

Local row inspection now uses individually labeled fields for each generic field, source column, and exact row-one header instead of requiring JSON. Reviewers can add and remove bindings, up to 50. The combined serialized selection remains limited to 16 KiB, with a 512-character limit per input; incomplete entries and non-uppercase column labels are rejected before source inspection. The domain projection still checks unique fields and columns, valid Excel addresses, and exact source headers. No fields, columns, or participants are inferred or approved.

Editing, adding, or removing a binding clears the displayed result and invalidates in-flight responses; clearing the local view also resets all selection inputs. The existing case, review, snapshot, source-byte, and approval-consistency checks and the production participant-routing blocker are unchanged. These controls are a temporary local inspection aid, not a population mapping approval or authorization to use real data.

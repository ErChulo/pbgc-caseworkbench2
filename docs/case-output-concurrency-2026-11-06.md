# Case-output operation and restoration guards — 2026-11-06

Final-output linking and export previously captured case state, then performed asynchronous reads, hashing and writes while the case or its inputs could change. A same-session guard now permits only one link/export at a time. Both controls are disabled while an operation or artifact-reference restoration is running. The operations check the active case, workspace and input revision after asynchronous work and immediately before writing. Changes to the manifest summary, plan-rule records, population items, unresolved items, linked artifacts or shared reviewer invalidate an in-flight operation and clear the prior export-success message. Case activation and switching also invalidate outstanding operations. If a file becomes unavailable or its bytes no longer match before export, export remains blocked as before.

When reopening a case, reference restoration is case- and request-bound and must finish before link or export starts. The local reference file is limited to 1 MiB and 256 entries; malformed, invalid or unreadable records block link/export instead of being silently overwritten. The user is told to inspect the local file and reopen the case; no reference file is changed on this failure. Missing files and valid empty lists remain supported. Individually rejected linked files are not restored and are reported separately. This is not a content or approval verification of those files.

The guards are **not filesystem transactions or cross-window locks**. Another window or external program can change workspace files after verification. A case change during an already-started atomic write cannot safely cancel or undo it; when the same case remains active, the UI warns that the file may have been saved and asks the user to inspect it and retry. If the case has changed, that warning is not shown in the new case. Users must inspect the prior case after interrupting a write. This feature does not revoke previously written output, authenticate reviewers or sources, or make any final-output stage ready.

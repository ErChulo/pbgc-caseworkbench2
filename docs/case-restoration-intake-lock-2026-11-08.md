# Case restoration and intake lock — 2026-11-08

Case activation now holds a same-session restoration guard while the evidence checkpoint and review state are restored and governed evidence records are refreshed. The case workspace actions are hidden during that interval, return to workspace home is disabled, and intake cannot begin. This prevents an early new intake from using an empty or older in-memory snapshot while the prior snapshot is still loading, and prevents normal navigation to a different case during that restoration. A status message explains the wait and advises reloading and inspecting the workspace if it does not finish.

If the evidence pointer, checkpoint, preserved content or review state cannot be verified, or restoration throws, intake and the other case action panels remain blocked. The user can return home; reopening retries restoration. The app does not rewrite a rejected pointer to recover. The error for an unexpected restoration failure warns that some records may already have changed, because governed refresh can write before a failure. The guard does not provide rollback.

Synthetic Chromium tests delayed a checkpoint-pointer read and confirmed that intake and navigation remained unavailable until restoration finished. Separate tests corrupted an existing inventory pointer and an existing review pointer, confirmed visible blockers, and checked the inventory pointer remained untouched. The delayed-read test also passed from an isolated built `file://` artifact with HTTP blocked; the synthetic governed production path passed in development and file modes. Tests used in-memory workspace handles, not the native office filesystem. Typecheck, lint, format, schema and contract checks passed; the isolated single-file build and verifier passed. The full unit/integration/contract run reported 1,199 passed, four skipped, and one Data Dictionary failure caused by missing approved Git LFS bytes.

This is not a cross-window lock or atomic transaction, cannot cancel an already-stuck filesystem operation, and does not stop an operation started in another tab or one already in flight before activation. The separate draft, output-reference and architecture loaders have their own lifecycles; this guard does not attest that all of them have completed. Missing pointers are still treated as absent, not proof that no historical state exists. Several persisted reads are not yet bounded. Locally asserted reviewer identity, source authority and actuarial approval remain unverified, as do real-data and external application execution. The existing browser-externalized Node warning remains. The application is not ready for real-data office testing.

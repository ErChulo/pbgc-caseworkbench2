# Local approved field lookup

The application can read the already-identified approved Data Dictionary as a local, user-selected reference. It checks the pinned byte size and SHA-256 before parsing, does not execute workbook macros, and keeps the resulting catalog in memory only. The workbook is not bundled, copied to a case workspace, uploaded, or committed. Selecting a new file removes the prior catalog even if verification fails; an older delayed selection cannot replace a later selection in the same session.

Lookup uses the existing table-qualified official catalog. Field and optional table searches are exact and case-sensitive (surrounding input whitespace is ignored). Duplicate field names are identified as ambiguous; results show the source sheet and row and at most 50 entries. These results are reference metadata only: this panel does not create mappings, approvals, case artifacts, or calculation inputs. Hash verification confirms the selected bytes match the pinned version, not that the source or a reviewer has authority. Case-data security, governance and end-to-end real-data readiness remain open as described in `in-office-real-data-readiness-2026-11-06.md`.

The browser tests use the same authorized workbook through `PBGC_DATA_DICTIONARY_PATH` and cover approved and altered bytes, ambiguous and table-qualified lookup, case sensitivity, a superseded asynchronous selection, and the development and isolated built `file://` application with outbound HTTP blocked. Tests skip these workbook-dependent browser cases if that local path is absent. The workbook was recovered from the user's connected `pbgc-the-book-of-job` and checked against the pre-existing approved digest; no resupply was needed. The browser workspace tests are not evidence of office deployment, independent actuarial validation, or external workbook execution.

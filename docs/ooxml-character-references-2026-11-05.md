# OOXML text character-reference handling

DOCX/PPTX passive text extraction now decodes XML's five predefined entities and decimal and hexadecimal numeric character references in one pass. Invalid XML code points, malformed or unknown references, invalid UTF-8 in XML parts, and DTD/entity declarations fail closed. Extracted numeric-reference text is available to the existing sensitive-text screen. Synthetic integration tests demonstrate the decoded text reaching that screen and rejecting unsafe cases. The parser version is now 1.2.0.

This is not a complete XML parser, OOXML validator, PII detector, malware scan, or a guarantee that all document text is extracted. Text split across runs, unsupported encodings, hidden content, and other structures require further work. The existing normal browser MIME-versus-ZIP mismatch hold remains unchanged. Previously persisted extractions and safety reviews are not automatically re-screened or invalidated by this parser version; they cannot be treated as evidence that the new parser or screen ran. A governed rescreen and review-history migration remains necessary before any production use. The app remains not ready for real-data office testing.

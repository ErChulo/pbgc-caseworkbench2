# Empty Plan Summary draft persistence — 2026-11-08

The Plan Summary panel previously initialized a draft only in memory; reopening the case did not display it, even if another review operation had happened to save it. The panel now requires a nonempty evidence checkpoint before initialization, saves the empty draft in the case review snapshot, verifies the saved pointer and snapshot by bounded readback, and restores an exact case-bound empty draft when the case reopens. It explicitly identifies the draft as not an approval. Initialization is serialized within the session, checks the case, workspace, evidence snapshot and in-memory review state before publication, and blocks case actions with a partial-save warning if persistence or readback fails.

The restoration verifier accepts only an empty draft with the expected section inventory, case ID, and consistent section and record hashes. A saved populated summary, summary decision history, unsupported shape, or inconsistent hash blocks case restoration instead of being overwritten or treated as approved. This is intentionally conservative: the existing UI does not yet provide a complete evidence-to-attribute authoring and decision-replay workflow, and this slice does not implement one. Cases with such saved data require inspection and a governed migration or replay implementation. No prior data are silently repaired or discarded.

Synthetic unit tests covered valid empty drafts, case mismatches, structural changes and populated drafts. Synthetic Chromium tests covered save/reopen, pointer tampering, a case switch during a pointer write, and an unsupported summary with a valid outer review hash. The save/reopen flow also passed in an isolated built `file://` artifact with HTTP blocked. Existing synthetic output concurrency, V1 panels and governed production tests passed. Typecheck, lint, formatting, schema, contract, isolated build and single-file verification passed. The full unit/integration/contract suite reported 1,202 passed, four skipped and one failure due to the unavailable approved Data Dictionary Git LFS workbook.

Hashes show local consistency, not source authenticity, reviewer authority, independent actuarial review or completeness. Same-session freshness checks are not a cross-window transaction, and an already-started write can finish after a case switch; another review operation may be in flight before its state reaches the current ref. Partial or orphan files may remain. Native office filesystem behavior, real case data and external Excel execution were not tested. The existing browser-externalized Node warning remains, and the application is not ready for real-data office testing.

# Workspace population verification

Architecture selection now reopens each approved workbook population from its content-addressed workspace object. It checks the current case snapshot's deterministic identity, source membership and size, reads bounded chunks (maximum 32 MiB source), verifies the source hash, re-inspects and re-detects the workbook, replays the decision, and compares the reconstructed and stored profile hashes and decision projections. Architecture inputs use the reconstructed workbook rather than the persisted profile. A source absent from the snapshot, a stale profile or old detector decision, malformed chunk, or mismatched bytes blocks this path. Re-inspection and renewed review may be required after detector updates.

The asynchronous build checks that the case, workspace, evidence snapshot, review state and catalog have not changed at its checkpoints; a newer build supersedes an earlier one. These checks do not provide a transactional lock across storage writes. Later committed review, snapshot, catalog and authored-rule changes invalidate the in-memory build outputs; see `architecture-output-invalidation-2026-11-06.md`. Persisted architecture files remain case-scoped immutable artifacts, not release authorization. Further lifecycle and concurrency hardening is required before production release.

This binds consistency to the current local snapshot, not identity, artifact eligibility, quarantine release, reviewer authority, or approval authenticity. It does not enable I/B routing: approved participant-row selection, field bindings and B-cell semantics remain unresolved. ZIP expansion metadata is not a trustworthy security boundary; see `population-source-screening-2026-11-06.md`. Synthetic tests cover current and altered source bytes, mismatched stored profiles, absent or invalid snapshots, malformed reads and freshness comparisons. Browser and Excel runtime verification remain outstanding.

# Plan-rule history verification and restoration

The wizard now validates the approved plan-rule contract before saving a case rule and before building with one. A bounded local JSONL reader checks each record's contract and content hash, duplicate identities, predecessor chains, and one matching recorded review event for every rule. Missing, reordered, truncated or modified records and orphan or duplicate events fail closed. Writes check the prior history against the current session and verify it again afterward. On case reopen or evidence refresh, records are restored only after current catalog governance, unresolved-item checks and byte-bound source reinspection pass. A synthetic Chromium test reopens a saved rule, removes its event, confirms restoration is blocked, then restores the event and reopens successfully.

Testing found a contract mismatch: the approved plan-rule schema allows six applicability dimensions, while the UI and scenario-selection rules also use dimensions such as `early-retirement-provision`. Those scenario-specific rule records are now blocked before persistence, with a visible explanation. The synthetic browser flow uses a schema-supported participant-group rule and a Single Run case control instead; it does not demonstrate the previously used early-retirement scenario. Reconcile the approved schema and scenario model through the governing change process, not by silently changing the contract. Existing incompatible saved records block history restoration and require review.

History checks establish internal consistency only. The event log and typed reviewer are not authenticated or signed; a case path does not prove authorship or authority. The underlying file append is read-modify-write and is not transactional across browser windows or all review operations. A failed later write can leave a partial record or event, which blocks future use rather than being repaired silently. Source inspection does not establish actuarial correctness or approval authority; previously written artifacts are not revoked. Final release remains blocked.
